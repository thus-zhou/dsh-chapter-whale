## 2. P1

### A-P1-05 `restore_trash` 不持章锁

`chapter_editor.py:1023-1174`：`commit_raw_bytes` 后恢复流程无条件把归档 versions 前插并把 `current` 设回恢复稿，未持 `_locked(project, chapter)`，也不检查并发 `save_version` 是否已把正文/index 改为新稿。实测正文是并发新稿、`index current` 仍是恢复旧 sha，`current_version` 标题/版本号与实际正文分叉；并发 `author_confirm` 也会被归档 receipt 覆盖。

**最小修复**：全程持章锁，或写回前 CAS（target.current 与磁盘 sha 都仍等于恢复稿），否则报 `restore_conflict` 并保留并发 entry；回执用 read-latest 合并。

### B4-01 改令把 awaiting_approval 置 held 后评估/恢复直接变 pending

`agent_hub.py:333,386,398-413,501-504,586-595`：`HOLDABLE_STATUSES` 含 `awaiting_approval`；`start_amendment` 无条件 supersede 全部 pending 卡，再把等待审批任务 hold；`/evaluate` deterministic `wait_and_redo` 把它改 pending；单独 `resume` 也因 awaiting 集合扫描不到 held 任务而变 pending。实测三条路径均可绕过审批；只传文字/`fallback=continue` 时任务留在 awaiting 但卡已 supersede，永久不可批。

**最小修复**：不要把 awaiting 置 held；只 supersede 本次实际影响任务；保留/重发其卡；resume 将 held 的等待审批任务恢复 awaiting；补 amend+evaluate、amend(continue)、amend(no task_ids)、amend+resume 矩阵。

### C3-01 平台层未接线

`writer_runner`/`worker`/`skill_executor` 对 world_state/quality/task_queue/context_manifests 的生产引用为 0；`build_context(persist=True)`、`latest_manifest()` 无生产调用，`task_queue` 只有 API 自身 claim。世界事实、质量、上下文 manifest、并发队列对真实写作/发布仍无约束。

**最小修复（产品决策）**：接入生成 prompt/发布门禁/真实 worker，或明确标 advisory 并删除“主路径约束”的对外宣称。

### E-01R 重新审查/润色抹掉发布回执

`writer_runner.py:1369-1378`、`studio.py:541-552` 用 `receipt={...}` 整章覆盖，未保留 `published_sha256/publish/staged_at`；写回执不走 `receipts.lock`。实测发布后 `/review`（即使 review_failed）或 `studio.polish` 后章节变 `unpublished`，DELETE 200。

**最小修复**：统一 `publication_state.update_receipt`（锁内读最新、保留发布字段）；已发布/已入队时拒绝或只更新 review；补 publish→review/polish→DELETE 409 测试。

### E-01B 升级前已发布章节未回填

`bridge.stage_project:525-537` 对 `uploaded/` 归档的 archived 章节只写 manifest 和 skipped，不写 `published_sha256`；0.7.5 旧书升级后 `_published_state` 仍是 unpublished，delete/split/merge 保护失效。

**最小修复**：归档分支对 `valid_receipt` 命中项调用 `publication_state.record_published(..., source="archive_backfill")`；或提供一次性迁移。
