# 05 · 全局权威数据契约、统一事务与安全恢复（P0 地基）

- **定位**：全套件 `00`–`09` 的**唯一核心数据契约权威源（Single Source of Truth）**。其余文档凡涉及实体主键、版本指纹、状态枚举、幂等键或存储权威的示例，一律以本文 §1 为准。
- **落地阶段**：一期 `v0.8.0-alpha` 优先建设。

---

## 1. 全局唯一权威数据契约总表（全套件统一口径）

### 1.1 核心实体身份与指纹（所有模块与 API 强制统一）
| 字段 | 规范格式 / 计算规则 | 权威职责 |
| --- | --- | --- |
| `project_id` | 现有 16 位十六进制项目 ID | 作品永久身份 |
| `chapter_uid` | `chuid_{uuid8}`（新建/首次纳管时生成，永不变更） | **章节永久主键**（所有后台任务、批注、发布快照、世界状态、回收站必须绑定 `chapter_uid`，防删章重建同号串章） |
| `chapter_number` | 正整数（`1, 2, ...`） | 对外展示与排序属性（非永久主键） |
| `version_id` | `ver_{seq:04d}_{uuid8}` | **正式版本唯一身份**（即使仅改标题、正文一字未动也生成新 `version_id`） |
| `version_seq` | 单章单调递增整数（`1, 2, ...`） | 人类可读版本序号 |
| `content_sha256` | 正文文件原始字节 SHA-256（兼容 `v0.7.5` 的 `sha256` 键名） | 字节完整性校验与 `objects/` 去重 |
| `body_digest` | LF 规范化并去行尾空白后的 SHA-256 | 内容语义校验与审查绑定 |
| `title_digest` | `sha256(nfc_trimmed_title.encode("utf-8"))` | 捕捉仅改标题 |
| `version_fingerprint` | **`sha256((content_sha256 + "\x00" + title_digest).encode("utf-8"))`** | 统一乐观并发与审批卡综合版本指纹（全套件统一使用 `\x00` 分隔） |
| `draft_id` | `drf_{uuid8}` | 单次活跃草稿唯一身份 |
| `draft_epoch` | 单章跨删除单调递增整数（永不回零） | 杜绝草稿删后重建 `revision=1` 的 ABA 覆写 |
| `draft_revision` | 当前 `draft_id` 内的单调递增整数 | 双端草稿并发写保护 |

> **实装兼容铁律（核对 `v0.7.5` [chapter_versions.py:552-558](../../../backend/integration/chapter_versions.py#L552-L558) 与 [app.py:2057](../../../backend/manager/app.py#L2057)）**：
> 1. `chapter_versions/index.json` **必须保留 `entry["current"] = <64位sha256>` 与 `meta["sha256"]` 不变**（保证回滚至 `v0.7.5` 时旧版 `current_version()` 按 `meta.get("sha256") == current` 100% 命中），以同级新增字段 `entry["current_version_id"]`、`meta["version_id"]`、`meta["content_sha256"]`、`meta["title_digest"]`、`meta["version_fingerprint"]` 承载新版独立版本身份；
> 2. `app.py:2057` 的 `/versions/{version}` 路径校验放宽为双格式 `r"(?:[0-9a-f]{64}|ver_\d{4}_[0-9a-f]{8})"`，`read_version` / `restore_version` 同时兼容 `ver_*` 与历史 64 位 `sha256`。

### 1.2 核心状态枚举权威定义
- **Hunk 状态**：`pending | applied_to_draft | committed | committed_modified | superseded | rejected`
- **批注聚合状态**：`open | conflicted | running | proposed | partially_applied | accepted | rejected | relocated_needed`
- **任务提交状态（`operation_scheduling.commit_state`）**：`running | held | committing | committed | aborted | interrupted | recovery_required | cancelled`
- **预算五态状态机（`request_budget` / `directive_budget_links`）**：`reserved | dispatched | settled | unknown_charge | released`
- **发布/创作四类独立权限状态**：`pass`（审查通过）、`chapter_settled`（允许续写下章）、`author_confirmed`（作者显式定稿）、`publish_authorized`（同意对外发布不可变快照）

### 1.3 全局 `op_id` 幂等契约（`idempotency_keys` 表）
所有写接口与触发 LLM 扣费的入口（`PUT /chapters`、`POST /annotations/run`、`POST /chief/messages`、`POST /book-directives/*`、`POST /sync-memory` 等）强制携带 `op_id`，落于 `.webnovel/workbench.sqlite3`（或跨书全局 `manager.sqlite3`）的 `idempotency_keys` 表：
```sql
CREATE TABLE IF NOT EXISTS idempotency_keys (
    actor TEXT NOT NULL,                  -- author | chief | worker
    project_id TEXT NOT NULL,             -- 未建书用 session_id
    action TEXT NOT NULL,                 -- 如 chapter_save / run_annotation / chief_message
    op_id TEXT NOT NULL,
    params_hash TEXT NOT NULL,            -- 规范化请求参数 SHA-256
    state TEXT NOT NULL,                  -- in_progress | completed | failed
    operation_id TEXT,                    -- 异步任务关联的 operation_id
    response_json TEXT,                   -- 完成后缓存的响应体
    created_at TEXT NOT NULL,
    expires_at TEXT NOT NULL,             -- 默认保留 24 小时后由 GC 清理
    PRIMARY KEY (actor, project_id, action, op_id)
);
```
- **并发重入与防误用规则**：
  1. 命中同一主键但 `params_hash` 不一致 → 直接返回 **HTTP `409`（`code: "op_id_params_mismatch"`）**，绝不误返回另一次操作结果；
  2. 命中 `state == 'in_progress'`（例如用户双击按钮时首个请求仍在执行）：若为异步任务且已有 `operation_id`，幂等返回 `202` 与该 `operation_id`；若为同步写接口，返回 `409 in_progress` 提示稍候；
  3. 命中 `state == 'completed'`：直接返回缓存的 `response_json`（零重复扣费、零重复建版）；
  4. 命中 `state == 'failed'`：允许携带相同或新 `op_id` 安全重试。

## 2. 存储架构减负：项目级 `.webnovel/workbench.sqlite3`

为避免把新增状态拆成满地零散 JSON 文件导致复杂的分布式跨文件锁与 GC 负担，明确划分两类存储边界：

| 存储类型 | 包含数据 | 设计理由 |
| --- | --- | --- |
| **纯文件（保留人类可读与 `v0.7.5` 兼容）** | `正文/*.md`、`大纲/*.md`、`设定/*.md`、`chapter_versions/{objects,index.json}`、`writer_receipts.json`、`story_plan.json`、`story_plan_meta.json` | 作者可用外部编辑器直接查看/备份，且完全兼容 `v0.7.5` |
| **项目级 `.webnovel/workbench.sqlite3`（SQLite WAL）** | **所有新增内部状态**：实时草稿（含 `draft_id / draft_epoch / draft_revision`）、批注与 Hunk、`patch_ledger`、规则豁免表、失效记录扩展、`idempotency_keys`、本地 FTS5 2-gram 搜索索引、小说世界状态事实与 `context_manifest` | 单库天然 ACID 事务、彻底消灭小文件碎片、草稿绝不碰 `chapter_versions/index.json`、大幅减轻跨文件事务负担 |

## 3. 轻量跨文件事务日志（`backend/integration/transaction_journal.py`）与读取一致性

由于所有新增内部状态已收口至 `workbench.sqlite3`，跨文件事务日志仅需保护极小范围的**「`.md` 磁盘文件 + 兼容旧 JSON（`index.json`/`writer_receipts.json`）+ `workbench.sqlite3`」**闭环。

### 3.1 事务记录与防漂移恢复规则
- 落盘位置：`<project>/.webnovel/transactions/tx_{tx_id}.json`；
- **关键恢复信任边界**：进程崩溃重启后重放 `tx_*.json` 时，恢复器**只信任 `tx.json` 中记录的明确 `from_path`/`to_path`、`version_id` 与不可变 `objects/{content_sha256}.txt`**，**绝不反查可能滞后的 `index.json` 或目录猜文件名**；每一步必须校验实际磁盘内容而非只看 `done` 标记。
- **读取一致性门面**：
  - 每次业务提交在 `workbench.sqlite3` 维护单调 `commit_generation`；
  - 当某章存在未完成的 `tx_*.json`（处于 `prepared`/`applying`）时，关键读取者（自动发布器、记忆同步、审稿、章节 API）通过统一读取门面检测到未完成事务，先触发快速恢复或返回 `409 recovery_in_progress`，**绝不读到“正文已 v6、回执和索引还是 v5”的半提交混合状态**。

## 4. 不可变发布快照、一致性备份与安全降级

### 4.1 不可变发布快照与最后一道执行门禁
- 每次入队或批准排期，在 `.publication/snapshots/pub_{approval_id}.json` 固化不可变快照（绑定 `platform`、`account_id`、`project_id`、`chapter_uid`、`chapter_number`、`version_id`、`content_sha256`、`body_digest`、`title`、`title_digest`、`contract_hash`、`scheduled_at`、`approval_id`）；
- **原子消费审批 + 发布前二次复验**：审批消费与发布任务创建在单事务内原子完成；到达排期时刻真正点击发布前，再次核验授权未被撤销且当前正式 `version_id` 未变动——若已演进为新版，自动暂停排期提示重确认；外部结果不明时禁止盲目重试，强制先走 `reconcile` 对账（外部平台无原生幂等键时不做虚假 Exactly-Once 承诺，坚守保守对账）。

### 4.2 跨存储一致性备份（备份代次屏障）
- 单靠 SQLite Online Backup API 无法自动对齐 `manager.sqlite3`、`costs.sqlite3`、`workbench.sqlite3` 与 `正文/*.md` 处于同一业务时刻；
- 执行作品/全局备份时采用**轻量备份屏障**：短暂暂停新提交（或等待活动 `tx_*.json` 清零，超时 5 秒降级提示）→ 调用 `sqlite3.Connection.backup()` 拷贝各库 + 原子复制文本与 `objects/` + 写入带 SHA-256 校验清单的 `backup_manifest.json` → 释放屏障；支持保存至用户指定的**其他磁盘目录**，并支持预览式安全恢复（ZIP 导入/恢复严格防路径穿越、防压缩炸弹、禁止覆盖任意系统路径）。

### 4.3 安全升降级与降级三类界定
| 场景 | 支持等级 | 规则说明 |
| --- | --- | --- |
| 新版读取/升级旧版作品 | **完整支持** | 升级前停 Worker、做一致性快照，幂等创建 `workbench.sqlite3` |
| 旧版 `v0.7.5` 读取新版作品 | **兼容范围内支持** | 不改 `operations`/`request_budget` 旧表列；`index.json` 保留 `entry["current"]=sha256`；`request_budget` 转 `released` 时同步清零 `tokens=0, cost_cny='0'`（防旧版 `costs.py:208` 误计已释放额度）；旧版读 `author_confirmed` 安全返 `False` 不抛异常 |
| 旧版 `v0.7.5` 修改新版作品 | **需走明确降级导出** | 因旧版不认识 `engine_version.lock`（无法指望旧程序自检锁文件），提供独立命令行/面板入口 **`rollback/export-legacy`**，将新版正文/大纲安全导出给旧版或从升级前快照恢复旧版，并妥善保留新版创作副本，同时提示严禁新旧两版本并发操作同一作品目录 |

## 5. 本地安全、运行时强制权限与防提示词注入

1. **运行时强制四主体权限（绝不相信模型自报角色）**：
   - 作者会话由宿主令牌/设备配对 Cookie 签发；主编/专业角色/Worker 由后端按任务签发**服务端绑定临时能力令牌**（限定 `project_id`、`chapter_uid`、允许动作与有效期）；
   - **硬禁止**：任何 Agent 与 Worker 均无权调用 `author-confirm`、无权自批 `agent_approvals`、无权直接对外发布或修改全局预算/供应商密钥。
2. **不可信创作资料隔离（防提示词注入）**：
   - 正文、参考示范 TXT、读者评论、外部导入文件一律包在 `<UNTRUSTED_MATERIAL>...</UNTRUSTED_MATERIAL>` 中，系统提示声明仅作材料分析不执行指令；后端 Tool Dispatcher 叠加参数白名单与权限硬拦截。
3. **Windows 路径与凭据安全**：
   - 路径校验同时拦截符号链接、**Windows Junction 与重解析点（`FILE_ATTRIBUTE_REPARSE_POINT`）**、保留设备名（`CON/PRN/AUX/NUL/COM1-9/LPT1-9`）及尾随空格/点号；
   - API Key 与平台 Cookie 沿用系统凭据保护，**绝不进入备份包、日志、SSE 事件与脱敏诊断包**；局域网访问（`--lan`）强制设备配对认证与 `Origin/Host` 校验，提示在可信局域网/HTTPS 下使用。
