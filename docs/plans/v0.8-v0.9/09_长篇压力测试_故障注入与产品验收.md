# 09 · 长篇规模压测、故障注入与核心质量验收（`v0.8–v0.9.5` 验证基线）

- **定位**：在 `04` 日常功能与接口回归测试之上，建立覆盖 **`v0.8–v0.9.5` 全周期** 的工业级验证体系——2A 即运行随机合并与畸形模型输出测试、三期增加 2-gram 双字中文检索与并发故障注入、四期完成 10–1000 章（300 万字）规模压测与 10 项核心长篇质量验收（外部 MCP 与 3000 章/72h 长测不纳入 0.9 范围）。

---

## 1. 长篇规模分级压力测试矩阵

针对长篇网文“前 10 章极快、写到 500 章卡死”的典型退化风险，建立五级固定压测数据集（脱敏合成中文长篇语料）：

| 压测等级 | 规模 | 重点检验模块与防退化指标 |
| --- | --- | --- |
| **L1 · 基础回归** | 10 章 / 3 万字 | 每次 PR 自动跑通全功能与并发基础校验 |
| **L2 · 常规连载** | 100 章 / 30 万字 | 章节目录、多文件大纲自愈、批注重定位与 FTS5 检索耗时 |
| **L3 · 长期百万字** | 500 章 / 150 万字 | 世界状态引擎事实检索、上下文组装预算裁剪、版本库 `index.json` 读写与 GC 速度 |
| **L4 · 超长篇极限** | 1000 章 / 300 万字 | 目录加载、`room/state` 快照体积、SQLite WAL 体积与 checkpoint 稳定性、全书改设定扫描内存峰值 |
| **L5 · 多书并跑** | 5 本 × 200 章并存 | 全局 4 槽位调度隔离、跨书并行不串书、瞬态信号与持久事件隔离、内存与句柄无泄漏 |

## 2. 可量化性能门禁（采用 P95/P99 + 超时降级，摒弃绝对硬毫秒）

> **测量说明**：以下为面向典型 Windows 10/11 本地桌面环境（NVMe/SATA SSD、开启默认 Windows Defender）设定的**初始验收目标值**（非已实测数据），压测报告必须注明基准硬件、杀毒扫描状态与数据集规模。由于杀毒软件扫描与磁盘瞬时负载不可控，文件锁与落盘统一以 **P95/P99 延迟 + 清晰超时降级** 衡量，不要求极端场景绝对 `< 50ms`。

| 关键指标 | 初始目标门禁 | 超标时的降级或诊断要求 |
| --- | --- | --- |
| 本地编辑器按键输入反馈 | `P95 ≤ 50ms` | 不得在 `onChange` 同步跑重 Diff 或全文正则 |
| 单章读取（含草稿与状态） | `P95 ≤ 200ms` | 历史版本正文按需懒加载，不随列表全量返回 |
| 普通临时草稿保存 | `P95 ≤ 300ms` | 遇临时文件占用自动退避，前端保留本地 `localStorage` |
| 普通正式版本保存 | `P95 ≤ 500ms` | 失效重建异步化不阻塞主保存响应 |
| 1000 章作品目录列表加载 | `P95 ≤ 2s` | 支持分段/虚拟滚动渲染，目录缓存按版本号增量刷新 |
| 百万字（500 章）本地全书检索 | `P95 ≤ 2s` | 基于 `workbench.sqlite3` FTS5 2-gram 影子表 + 分页返回；双字人名召回率 100% |
| 正常本地 SSE 事件推送端到端延迟 | `P95 ≤ 200ms` | 本地回环 `/internal/events/notify` 唯一主通道优先（`app.py:412` 保留 `stderr=STDOUT` 零日志回归），500ms 短读兜底 |
| 正常输入自动草稿防抖落盘 | `≤ 2s` | IME 组合输入期间暂停覆写 |
| 无冲突文本三方合并错误率 | **测试用例中 = 0** | 任何歧义宁转冲突或重指位，绝不静默误改 |
| 正式正文静默覆盖次数 | **0 次** | 必由 `version_id` / `draft_id+epoch` / `lease_id` 拦截 |
| 未经作者授权对外发布次数 | **0 次** | 不可变发布快照 + 审批防重放硬门禁 |
| 活跃引用快照/正式版本被 GC 误删 | **0 次** | 引用关系全扫描硬保护 |

## 3. 随机性质测试（Property-based）与崩溃故障注入测试

### 3.1 随机性质测试与多步状态机序列测试（2A `v0.8.2` 即上线门禁）
使用 dev/CI 专用 `Hypothesis` 或**零外部依赖的 Python 标准库固定种子生成器（`random.Random(seed)`，严禁将测试库写入 `requirements-runtime.lock`）**对 `text_merge.py`、`annotations.py` 与草稿/版本状态机执行至少 **1,000 组随机变换与多步动作序列测试**：
- 随机生成含中文标点、重复台词、emoji 代理对、`\r\n` / `\n` 混排、空行的章节文本；
- 随机注入多步序列：前文增删行、选区整段上下搬移、相邻多 Hunk 乱序分次采纳、`custom_text` 微调、采纳请求飞行中继续打字、反向补丁撤销再重采纳、丢草稿回退与选区内部随机篡改；
- **必须成立的不变量**：
  1. 无重叠场景合并结果满足可还原性，未选中区域 100% 一字未变；
  2. 重复台词叠加前文删除绝不静默命中错误行；
  3. 任意冲突或歧义场景下，作者修改与 AI 候选**双方文本零丢失**；
  4. 同步校验锚点重定位参数（初始 `0.78` 相似度 / `0.15` 分差）在真实网文语料集上的假阳性率（目标 `0%`）与召回率，于 2A 调优固化；
  5. 三期同步追加 **2-gram FTS5 中文双字人名（如「林溪」「老周」）专项召回测试**，验证 500 章样本下双字/三字实体召回率 100%。

### 3.2 崩溃故障注入测试（Chaos / Crash Injection，8 类故障点）
通过受控 Hook 在以下 **8 个精确故障点** 强杀进程或注入异常，重启后验证零数据损坏、零静默丢稿：
1. `transaction_journal` 写完正文、尚未改名及更新 `index.json` 时强杀 → 重启仅信 `tx.json` + `objects/` 自动向前补齐或安全回滚；
2. 写完权威 `AI规划-*.md`、尚未更新 `story_plan.json` 时强杀 → 重启 `recover_plan()` 读到一致新结局；
3. Worker 写完正文进入 `committing`、尚未更新 DB 为 `committed` 时强杀（且验证 `committing` 状态严禁续租、超时转 `recovery_required`） → 重启凭 `commit_op_id` 对账推进为 `committed` 并补发事件；
4. Worker 在 `reserved` 与 `dispatched` 两个状态分别被强杀 → `reserved` 立即释放余额，`dispatched` 准确转 `unknown_charge` 风险额度；
5. 旧 Worker 失联 30 秒后唤醒尝试写盘 → 被新 `lease_id` Fencing 拦截 0 字节写入；
6. 定时发布队列已授权 `v5`，发布前 1 分钟作者保存 `v6` → 发布引擎自动暂停排期并生成待拍板卡，0 误发 `v6`；
7. 模拟 Windows `WinError 32` 锁住旧标题 `.md` 文件 3 次后释放 → `rename_with_retry` 自动退避成功；
8. 模拟读入含提示词注入的恶意读者评论与参考 TXT → 主编与所有角色拒绝执行其中的删除/发布指令。

### 3.3 模型畸形输出、限流风暴与越权测试（2A / 2B / 三期必跑）
针对免费池、弱模型与真实网络抖动，建立 5 类专项故障模拟：
1. **HTTP 200 空响应 / 半截截断流**：`ModelGateway` 识别为空/截断失败，不写盘污染草稿或候选，并正确结算或转 `unknown_charge`；
2. **精修 XML 畸形与闭合标签撞车**：模拟返回重复 `<patch id>`、段落号越界、或网文正文恰好包含字面 `</replacement>`，校验解析器防截断并至多执行 1 次格式重试；
3. **429 限流风暴与隐私域隔离**：主供应商突发连续 429 时槽位自动退避不阻塞 P0 交互与其他供应商；且 `local_offline` / `private_api` 绝不静默降级至 `free_pool_shared`；
4. **慢客户端 SSE 积压**：模拟前端卡顿不读流超过 256 帧，服务端先丢瞬态帧再下发 `resync_required` 断开，Manager 内存零泄漏；
5. **审批重放与越权工具调用**：重复提交同一已审批 `approval_id`、修改正文后提交旧审批卡、或由 Worker 伪造审批提交，全部返回 403/409 硬拒绝。

## 4. 长篇小说写作质量专项评测集（10 项核心指标）

解决“前三章写得不错，但第 100 章彻底吃书”的评测盲区，建立固定素材库（涵盖悬疑、都市异能、玄幻三种典型网文结构），针对**真实付费模型与免费池弱模型**分别执行多次重复运行（统计成功率、平均成本、最差结果、纠偏次数与上下文长度）：

| 编号 | 评测专项 | 验收判定方式 |
| --- | --- | --- |
| **Q1** | **远期人物记忆** | 第 80 章出场人物是否仍准确遵守第 3 章确立的外貌特征、口癖与核心秘密 |
| **Q2** | **道具状态追踪** | 第 30 章获得、第 45 章转交、第 60 章销毁的道具，第 80 章不再凭空出现 |
| **Q3** | **角色认知边界** | 未被告知凶手身份/暗线秘密的角色，在对白与心理中不提前泄密 |
| **Q4** | **剧情时间线因果** | 案发顺序、季节天气、伤口恢复天数跨 20 章不发生倒置矛盾 |
| **Q5** | **长期伏笔回收** | 第 6 章埋下的关键线索在第 30 章可被 `06` 检索引擎召回并自然推进 |
| **Q6** | **文风与视角稳定** | 连续 10 章保持固定叙事视角与作者确认的风格偏好，无突然上帝视角与高频 AI 总结腔 |
| **Q7** | **弱模型 / 免费池适配** | 弱模型输出残缺 JSON/错误标签时，XML 定界与 6 大模板安全兜底不崩任务 |
| **Q8** | **人机并发零污染** | 手改正文与 AI 并行润色互不覆盖，且未采纳/已废弃候选 0 泄漏进正式记忆 |
| **Q9** | **全书改设定因果完整** | 把第 12 章配角“死亡改为失踪”，影响分析不仅命中姓名，还报出葬礼/遗产/复仇动机等间接关联章 |
| **Q10** | **上下文清单可诊断** | 抽查任意一章生成的 `context_manifest`，可完整追溯所读事实来源并复现检索结果 |

## 5. `v0.9.5` 验收范围边界（明确延后项）

本验证体系随 **`v0.9.5`** 同步收口达标；以下超长/外部生态评测项明确不纳入 `v0.8–v0.9.5` 强制门禁，留待 `v0.9` 稳定后再视需要开启：
- **外部 MCP Server 工具暴露与外部 Agent 联调测试**（本轮聚焦码章鲸内置主编室与双端直写体验闭环）；
- **3,000 章（900 万字）或 72 小时连续无人值守老化压测**（`v0.9.5` 以 1,000 章 / 300 万字与 5 书并发为上限门禁）；
- **20 项大规模人工盲测评测**（`v0.9.5` 聚焦上述 Q1–Q10 十项可复现核心长篇质量门禁）。
